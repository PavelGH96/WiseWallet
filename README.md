# WiseWallet v3.32

Личный учёт доходов, расходов и кредитов. Однофайловое PWA-приложение без сборки: работает на ПК и iPhone, офлайн, с опциональной синхронизацией через Supabase.

## Что нового в v3.32 — обязательный вход по email/паролю

Раньше приложение было «локальным первым» без аккаунтов, а доступ к данным охранял «ключ синхронизации» в общей таблице `ww_state` с открытыми политиками. Теперь модель такая же, как в CRM WiseBase.

| Что | Как работает |
|---|---|
| **Экран входа при запуске** | Без аккаунта приложение не открывается: email + пароль, регистрация, «Забыли пароль?» |
| **Настройки подключения зашиты в файл** | Константы `WW_SB_URL` и `WW_SB_KEY` в `index.html` (блок v3.32). Заполните один раз — и на любом устройстве достаточно ввести почту и пароль. Пока они пустые, на экране входа есть свёрнутый блок «Подключение к Supabase» |
| **Синхронизация только под сессией** | Всё пишется в `ww_user_state` с токеном пользователя; RLS `auth.uid() = user_id` не отдаст строку никому другому |
| **Перенос старых данных** | При первом входе строка из `ww_state` по старому ключу синхронизации одноразово переносится в аккаунт (берётся та версия, которая новее) |
| **Старый режим убран** | Поле «Ключ синхронизации» больше не показывается; при зашитых константах скрываются и URL с anon key |
| **Выход из аккаунта** | Перед выходом делается последняя синхронизация, затем локальная копия и сессия удаляются — на чужом устройстве не останется ничего |
| **Смена пароля** | Настройки → Аккаунт Supabase → Сменить пароль |
| **Облачные резервные копии привязаны к аккаунту** | `ww_snapshots` ключуется `user_id`, политики — `auth.uid()::text = sync_id` вместо прежних открытых |
| **Офлайн не сломан** | Если сети нет, но на устройстве есть сохранённая сессия, приложение открывается с локальными данными, а синхронизация догоняет при появлении связи |

### Первый запуск после обновления

1. Выполните `supabase_schema.sql` в SQL Editor (шаги указаны в самом файле вверху).
2. Authentication → Providers → Email: включить (без подтверждения почты — выключите «Confirm email»).
3. В `index.html` найдите `var WW_SB_URL = "";` и `var WW_SB_KEY = "";` и вставьте свои значения.
4. Откройте приложение → «Создать аккаунт» → войдите. Старые данные подтянутся автоматически.

> Ограничение: режим наблюдателя с кодом доступа (просмотр без права правки) по-прежнему работает через старую общую таблицу и экран входа не показывает — такому устройству аккаунт не нужен.

### Горячие клавиши

`N` новая операция · `T` перевод · `/` поиск · `1…9` разделы (дашборд, операции, бюджеты, цели, кредиты, календарь, планировщик, аналитика, настройки) · `B` уведомления · `H` история · `X` режим выбора · `V` голос · `Ctrl+Z` / `Ctrl+Shift+Z` · `Esc` закрыть · `?` подсказка

> Журнал и отметки «прочитано» хранятся вместе с данными (localStorage + Supabase-синхронизация). Стек Undo/Redo — в памяти текущей сессии. В режиме наблюдателя изменяющие действия заблокированы.

## Запуск

**Локально:** просто откройте `index.html` в браузере — всё работает без сервера (кроме установки PWA).

**GitHub Pages (рекомендуется):**
1. Создайте репозиторий на GitHub (можно приватный + Pages).
2. Загрузите все файлы в корень репозитория.
3. Settings → Pages → Deploy from branch → `main` / root.
4. Откройте выданный URL на iPhone → Поделиться → «На экран «Домой»» — получите полноценное приложение.

## Синхронизация Supabase (опционально)

1. Создайте бесплатный проект на supabase.com.
2. Выполните `supabase_schema.sql` в SQL Editor.
3. В приложении: Настройки → Синхронизация Supabase → вставьте URL проекта и anon key (Settings → API).
4. На втором устройстве укажите те же URL, key и **тот же ключ синхронизации**.

Синхронизация автоматическая: после каждого изменения и при восстановлении сети. Побеждает более свежая версия данных.

## Что нового в v2.0

1. **Вход по email/паролю (Supabase Auth)** — личная таблица `ww_user_state` с RLS: данные видит только владелец. Выполните `supabase_schema.sql` (часть 2) и включите Email-провайдер в Supabase. Без входа продолжает работать старый режим с ключом синхронизации.
2. **PIN-код** — Настройки → Безопасность (блокировка при открытии и после 2 минут в фоне).
3. **Защита от конфликтов синхронизации** — если данные менялись на двух устройствах одновременно, приложение спросит, какую версию оставить.
4. **Автопроведение регулярных платежей** — панель «К проведению» на главной: «Провести», «Провести все» или «Пропустить».
5. **График погашения кредитов** — в карточке кредита (Изменить → «График платежей»): помесячный план, переплата, дата закрытия и расчёт досрочного погашения.
6. **Резервные копии и отмена** — автоснимки каждые 6 часов (последние 5, Настройки → Резервные копии) + кнопка «Отменить» после удаления операции.
7. **Прогноз остатка на 12 месяцев** — новый график во вкладке Аналитика.
8. **Переводы между счетами** — вкладка Операции → «⇄ Перевод» (не искажают статистику доходов/расходов).
9. **PWA** — кнопка установки, индикатор офлайна и браузерные уведомления о предстоящих платежах (Настройки → Приложение).
